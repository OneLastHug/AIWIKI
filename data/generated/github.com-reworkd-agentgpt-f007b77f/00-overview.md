# 项目整体介绍

AgentGPT 是一个把“设定目标并让 AI agent 自主拆解执行”的体验放进浏览器的全栈项目。仓库 `README.md` 对它的描述是：用户为自定义 AI 命名并输入目标，系统会尝试通过思考任务、执行任务、从结果中学习来推进目标。结合源码可以看到，这个项目并不是单纯的聊天窗口；它把一次目标执行拆成多个 loop step，例如 `start`、`analyze`、`execute`、`create`、`summarize`、`chat`，这些枚举出现在 `platform/reworkd_platform/schemas/agent.py`。因此，理解项目时应把它看作“前端 orchestrator + 后端 LLM/tool API + 数据库持久化”的组合。

核心能力主要有四类。第一，前端提供目标输入、运行控制、聊天窗口、任务消息流和历史 agent 页面。`next/src/pages/index.tsx` 是主页面，用户输入 goal 后会创建 `DefaultAgentRunModel`、`MessageService`、`AgentApi` 与 `AutonomousAgent`，然后调用 `newAgent.run()`。第二，浏览器端维护 agent 生命周期和任务队列。`next/src/services/agent/autonomous-agent.ts` 内部持有 `workLog`，初始放入 `StartGoalWork`，随后按队列执行 `AnalyzeTaskWork`、`ExecuteTaskWork`，并在任务队列为空时停止。第三，后端提供 FastAPI agent API。`platform/reworkd_platform/web/api/agent/views.py` 暴露 `/start`、`/analyze`、`/execute`、`/create`、`/summarize`、`/chat`、`/tools` 等路由，其中执行、总结、聊天返回 `StreamingResponse`。第四，系统把登录、agent 历史、任务记录和运行计数写入 MySQL。前端 Prisma schema 在 `next/prisma/schema.prisma`，后端 SQLAlchemy 模型在 `platform/reworkd_platform/db/models`。

主要模块可以按目录理解。`next` 是 Next.js 13 + TypeScript 前端，包含 Pages Router 页面、组件、Zustand store、tRPC 路由、NextAuth 配置、Prisma 模型和与后端 FastAPI 通信的 service。`platform` 是 Python 3.11 FastAPI 后端，入口是 `platform/reworkd_platform/__main__.py`，应用构造器是 `platform/reworkd_platform/web/application.py`，核心业务集中在 `web/api/agent`。`cli` 是 Node.js 初始化工具，`cli/src/index.js` 通过 Inquirer 询问配置，并由 `cli/src/envGenerator.js` 生成 `next/.env` 与 `platform/.env`。`db` 只放数据库镜像相关文件；根目录 `docker-compose.yml` 编排 `frontend`、`platform`、`agentgpt_db` 三个服务。

适合初学者的切入点是先从“用户点击运行后发生什么”入手。先读 `next/src/pages/index.tsx`，看 `handleNewAgent` 如何检查 session、构造模型和 API；再读 `next/src/services/agent/autonomous-agent.ts`，理解 `run()` 的循环；然后读 `next/src/services/agent/agent-work` 下的 work 类，确认每一步如何调用 `AgentApi`。后端侧从 `platform/reworkd_platform/web/api/agent/views.py` 进入，顺着 `get_agent_service` 找到 `OpenAIAgentService`，再看 `tools/tools.py` 和各个 tool。读完这条链，再回头看 UI 组件和数据库表会更轻松。

需要特别注意的是，这个项目有两套和 agent 相关的数据模型。前端 Prisma 的 `Agent`、`AgentTask` 用于保存可回看的 agent 历史；后端 SQLAlchemy 的 `AgentRun`、`AgentTask` 表名映射到 `agent_run`、`agent_task`，用于记录运行 loop 和限制最大循环次数。它们都连到同一个 MySQL 数据库配置，但职责不同。根据当前文件推断，前端历史保存由 tRPC `agentRouter` 负责，后端 loop 记录由 FastAPI dependency validator 在每个请求前创建。
