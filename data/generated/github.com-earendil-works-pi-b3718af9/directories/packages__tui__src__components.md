# 子系统：packages/tui/src/components

## 解决什么问题
这个目录提供 TUI 层可复用的基础组件和中等粒度控件，目标是把“怎么在终端里把一块 UI 画出来、怎么处理输入、怎么展示列表/文本/加载态”这些重复逻辑收敛起来。根据当前片段推断，它不是业务流程本身，而是给上层页面和交互视图提供积木：比如输入框、选择列表、编辑器、文本截断、加载指示、Markdown 展示、图片占位/渲染、设置项列表等。

它的价值在于统一外观与交互行为，避免各个页面各写一套 terminal component。上层只需要组合这些组件，就能搭出对话界面、设置界面、结果展示区和状态提示区。

## 相关目录和文件
当前目录下的文件可以分成几组理解：

- 布局与容器类：`box.ts`、`spacer.ts`，负责基础排版、留白和结构组织。
- 文本与展示类：`text.ts`、`truncated-text.ts`、`markdown.ts`，负责普通文本、截断显示和富文本渲染。
- 输入与交互类：`input.ts`、`editor.ts`、`select-list.ts`、`settings-list.ts`，负责用户输入、可编辑内容和列表选择。
- 状态反馈类：`loader.ts`、`cancellable-loader.ts`，负责等待态和可中断的加载流程。
- 媒体与内容类：`image.ts`，负责图片相关展示或占位。

从目录命名看，这一层是 `packages/tui/src` 内部的共享 UI 基座，上层页面应当直接复用这里的组件，而不是自己拼接底层渲染细节。

## 核心对象
核心对象不是单个“大类”，而是一组职责单一的小组件模块：

1. `input` 类组件，承担文本输入和焦点交互。
2. `editor`，通常用于更复杂的多行编辑或可编辑内容场景。
3. `select-list`、`settings-list`，承担可选项浏览、选中态、设置项导航。
4. `markdown`、`text`、`truncated-text`，负责把模型输出或 UI 文案稳定地呈现到终端宽度里。
5. `loader`、`cancellable-loader`，负责异步任务中的反馈和取消语义。
6. `box`、`spacer`，负责把前面的内容组合成可读的版面。

根据当前片段推断，这些文件大概率通过统一的 props 约定被上层页面组合，形成一致的视觉和键盘操作体验。

## 运行流程
典型流程是：上层页面先决定展示哪一类内容，再把状态和事件交给这里的组件渲染。比如用户输入时，`input` 接收键盘事件并回传字符串；需要选择时，`select-list` 根据当前高亮索引渲染选项并处理上下移动；模型输出到来后，`markdown` 或 `text` 负责把内容以终端友好的方式显示；异步请求进行中，`loader` 或 `cancellable-loader` 给出等待态。

这些组件通常不会单独驱动业务，它们更像“渲染和交互适配层”。真正的状态切换、请求发送、会话推进，应该在 `packages/tui/src` 的页面或控制逻辑里完成，再把结果喂回组件。

## 上下游依赖
上游依赖主要是 TUI 的页面层和交互控制层：它们决定何时展示输入、何时展示列表、何时显示加载态、何时渲染 Markdown 或图片。换句话说，这个目录被更高层的视图逻辑消费。

下游依赖则是更底层的终端渲染与事件模型。虽然当前片段没有展开实现，但从文件职责看，这些组件必然依赖 TUI 运行时的布局、键盘输入、文本测量和重绘机制。`markdown`、`truncated-text` 这类组件还会依赖终端宽度、换行和截断规则；`image` 则可能依赖专门的图片显示能力或降级策略。

如果把整个 TUI 看成一条链，这个目录位于“页面状态”与“底层终端渲染”之间，是承上启下的一层。

## 修改时最容易踩的坑
第一，终端宽度变化是常见问题。`truncated-text`、`markdown`、`box` 这类组件最怕内容溢出或布局抖动，改动时要确认窄屏和宽屏都能读。

第二，输入交互要保持一致。`input`、`editor`、`select-list` 这类组件如果键盘行为不统一，上层页面会立刻变得难用。

第三，别把业务逻辑塞进组件。这里更适合放显示和交互封装，不适合直接发请求或改会话状态，否则后续复用会很痛。

第四，加载与取消语义要清楚。`loader` 和 `cancellable-loader` 名字已经提示它们处理的是不同状态，别把“等待中”和“可中断”混成同一套表现。

第五，图片和 Markdown 往往是最容易出现降级差异的地方。终端环境不稳定，改 `image.ts`、`markdown.ts` 时要考虑无能力设备和内容过长时的退化表现。

## 推荐阅读顺序
1. 先看 `box.ts`、`spacer.ts`，理解这个目录的基础布局手法。
2. 再看 `text.ts`、`truncated-text.ts`、`markdown.ts`，把文本展示规则建立起来。
3. 接着看 `input.ts`、`editor.ts`、`select-list.ts`、`settings-list.ts`，理解交互组件的组织方式。
4. 然后看 `loader.ts`、`cancellable-loader.ts`、`image.ts`，补齐状态反馈与媒体展示。
5. 最后回到上层 `packages/tui/src` 的页面或容器代码，把这些组件如何被组合起来串起来看。

整体上，这个目录是 `packages/tui` 的“可复用 UI 零件库”。先认清每个模块负责什么，再去看上层页面的拼装方式，会比从业务流程倒读更快。
