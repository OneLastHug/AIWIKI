# 目录：docs/prds/conversations/acp

## 它负责什么

`docs/prds/conversations/acp` 是 ACP 单聊功能的 PRD 拆分目录，角色不是实现代码，而是“需求地图”和“验收口径”的集中入口。它把原始 `prd-acp-scenarios.md` 中与 ACP 单人对话相关的功能点按模块拆开，排除了团队协作 `F-TEAM-*` 和定时任务 `F-CRON-*` 范围，最终形成 51 个独立功能点的索引与模块说明。

从目录内容看，这里关注的是一个 ACP 会话从创建、连接、发消息、流式展示、权限审批、配置恢复、错误处理到技能和 MCP 工具注入的完整产品行为。它不是按前端组件、主进程服务或 IPC 接口组织，而是按用户可感知的功能域组织：会话生命周期、消息与文件、AI 配置、权限、展示、可靠性、技能扩展。读这个目录的主要收益，是先建立“ACP 单聊应该具备哪些能力、哪些已实现、哪些部分实现、哪些未实现、哪些 E2E 被 skip”的全局认识，再去代码里找对应实现。

`README.md` 还承担状态总表职责：列出每个功能点编号、标题、当前实现状态、归属模块和 skip 白名单。它是判断范围边界的首选入口，尤其适合确认某个能力是否属于 ACP 单聊，或是否已经被合并到其他功能点中。

## 直接子目录地图

该目录当前没有直接子目录，只有一组 Markdown PRD 文件。因此这里的“地图”更像模块文件地图，而不是文件树层级地图。

`README.md` 是总索引，给出模块文件、功能点总表、状态统计和 skip 白名单。

`session.md` 覆盖 `F-SESSION-*`，负责会话生命周期，包括创建新会话、进入会话建立连接、停止回复、断连恢复、空闲释放、重置、删除、查看状态、会话迁移、AI 回复完成处理等。

`messaging.md` 覆盖 `F-MSG-*` 和 `F-FILE-02`，负责用户消息发送、AI 回复期间的队列、文件引用、首条消息规则注入、隐藏/静默消息、输入历史、重试撤销、`/btw` 追加上下文，以及 AI 读写文件能力。

`config.md` 覆盖 `F-CONFIG-*`，负责模型切换、会话模式切换、参数设置、模型与模式信息展示、响应超时、免确认模式迁移、Codex 沙盒安全级别联动、配置保存恢复、后端能力缓存等。

`permissions.md` 覆盖 `F-PERM-*`，负责 AI 操作审批、确认/拒绝、免确认或 YOLO 模式、待确认操作列表，以及会话创建时的模式与权限初始化。

`display.md` 覆盖 `F-DISPLAY-*`，负责实时逐字输出、思考过程、工具调用、执行计划、网页预览、上下文用量、斜杠命令、请求追踪、环境/健康检查和可用后端列表等界面反馈。

`reliability.md` 覆盖 `F-RELIABILITY-*`，负责连接超时、AI 回复超时、启动失败提示、本地缓存修复、多候选安装策略、发送异常恢复等错误和恢复路径。

`skills.md` 覆盖 `F-SKILL-*`，负责技能自动发现与注入、指定技能注入，以及 MCP 工具服务注入。

## 关键入口

最关键入口是 `docs/prds/conversations/acp/README.md`。它先说明该目录由 PM 从 `prd-acp-scenarios.md` 抽取 ACP 单聊功能点，并说明排除范围；随后用“模块文件”表把七个模块和编号范围对应起来；再用“功能点总表”列出 51 个功能点的标题、状态、模块和 skip 白名单；最后给出状态统计和 E2E skip 原因。学习时应先读这里，避免直接进入某个模块后误判全局状态。

第二类入口是各模块文件的一级标题和功能点标题。例如 `session.md` 的标题是“ACP 单聊 - 会话管理”，并声明覆盖 `S-LIFE-01 ~ S-LIFE-17`；`messaging.md` 声明覆盖 `S-MSG-01 ~ S-MSG-12, S-FILE-03`；`display.md` 声明覆盖 `S-UI-01 ~ S-UI-17` 的一部分。这些“覆盖技术场景”是从产品场景编号跳转到功能点编号的桥梁。

第三类入口是每个功能点块内部的固定结构：用户故事、前置条件、正常流程、异常情况、不同 AI 后端差异、验收标准、覆盖场景。不是每个功能点都有全部小节，但整体写法一致。想确认某个功能的实现边界时，优先看“实现差距”“异常情况”和“验收标准”，它们比标题更能说明真实要求。

## 主流程位置

ACP 单聊主流程可以按会话使用链路串起来，而不是按文件顺序机械阅读。

第一段是会话启动链路，主要在 `session.md`。用户创建会话对应 `F-SESSION-01`，进入会话并建立连接对应 `F-SESSION-02`。这里会同时恢复上下文、模型、会话模式，并加载用户配置、内置、扩展贡献的 MCP 工具服务。断连自动处理、空闲释放、重置、删除和迁移也是同一生命周期域。

第二段是消息发送链路，主要在 `messaging.md`。用户发送文本消息对应 `F-MSG-01`，文件引用对应 `F-MSG-02`，首条消息规则注入对应 `F-MSG-03`，隐藏/静默消息和 `/btw` 追加上下文则描述更高级的消息变体。AI 读写文件作为 `F-FILE-02` 被放在该模块里，说明文件能力在产品视角上属于对话消息上下文的一部分。

第三段是 AI 执行和反馈链路，主要在 `display.md` 与 `permissions.md`。流式文本、思考过程、工具调用、执行计划、网页预览等都在 `display.md`；当工具调用需要用户授权时，审批卡片、确认/拒绝、待确认列表和免确认模式由 `permissions.md` 描述。两者共同构成“AI 正在做什么、用户是否要介入”的交互主线。

第四段是配置与恢复链路，主要在 `config.md` 和 `reliability.md`。模型、模式、参数、超时、沙盒安全级别、配置保存恢复等属于正常使用中的偏好控制；连接超时、回复超时、启动失败、本地缓存损坏、发送异常恢复等属于失败路径。根据当前片段推断，这些需求是后续查找实现时的重要索引，因为它们经常跨越 UI、会话服务、后端适配器和持久化层。

第五段是能力扩展链路，主要在 `skills.md`。技能自动发现、手动指定技能、MCP 工具服务注入决定 AI 会话启动时拿到哪些额外能力。它和 `session.md` 的进入会话流程、`messaging.md` 的首条消息注入、`display.md` 的工具调用展示都有交叉关系。

## 推荐阅读顺序

建议先读 `README.md`，重点看模块表、功能点总表、状态统计和 skip 白名单。这样可以先知道当前 ACP 单聊范围内有 43 个已实现、6 个部分实现、2 个未实现功能点，也能提前记住 `F-MSG-07`、`F-RELIABILITY-06` 等未实现或待确认项。

然后读 `session.md`，因为会话生命周期是其他模块的前提。特别关注 `F-SESSION-02`，它把连接、认证、MCP 注入、上下文恢复、模型和模式恢复都串在一起，是理解主流程的核心。

第三读 `messaging.md`，关注 `F-MSG-01` 和 `F-MSG-02`。一个定义消息从输入到 AI 回复的基础路径，另一个定义文件如何进入上下文。这里的“部分实现”差距也很关键，例如队列多消息合并、文件引用去重、路径标记剥离等。

第四读 `display.md` 和 `permissions.md`。这两份最好连着看，因为工具调用展示和权限审批通常在同一轮 AI 执行中出现。前者回答“界面如何展示 AI 的进度”，后者回答“哪些操作需要用户确认以及如何确认”。

第五读 `config.md`、`reliability.md`、`skills.md`。这三类是对主链路的增强：配置决定会话行为，可靠性决定异常恢复，技能与 MCP 决定 AI 可用能力。读完这些，再回到 `README.md` 的 skip 白名单复核一遍，可以更准确地区分产品预期、当前实现差距和测试跳过项。

## 常见误区

不要把这个目录当成代码实现目录。它是 PRD 文档目录，里面没有组件、服务、IPC 或后端适配器实现。要找实现，需要拿功能编号和标题再去源码中搜索对应 UI、会话管理、ACP 后端适配和测试。

不要只看“已实现”就认为所有验收标准都完全稳定。`README.md` 的 skip 白名单显示，一些已实现功能仍有待确认边界，例如 `F-SESSION-10` 的 turn 完成边界、`F-DISPLAY-07` 的 token 统计双路径，以及 `F-PERM-03` 的 codebuddy 差异。

不要忽略“部分实现”开头的实现差距说明。`messaging.md`、`permissions.md`、`display.md`、`skills.md` 中的部分实现项通常已经具备主路径，但缺少某些产品细节，例如 OAuth 认证引导 UI、健康检查细分、文件引用去重或队列合并。

不要把 MCP 工具服务理解成每条消息动态刷新。`skills.md` 明确说明 MCP 工具服务主要在会话建立时注入，会话中途新增或修改配置通常需要重新进入会话才生效；禁用服务也主要影响新建会话。

不要把免确认模式等同于无条件自动通过所有请求。`permissions.md` 中的免确认逻辑强调“带有可选项的操作请求”可以自动处理，没有可选项的请求不会被自动处理，不支持免确认的后端也不应展示该模式。

不要把 ACP 单聊范围扩大到团队协作或定时任务。`README.md` 明确说明本目录排除了 `F-TEAM-*` 和 `F-CRON-*`，这些能力即使与会话复用或权限模式有关，也不属于这里的主文档范围。
