## 推荐阅读顺序

1. 先看 `docs/prds/workspaces/README.md`，确认这个目录的定义和范围。
2. 再横向对照 `docs/prds` 下的相邻主题目录，理解 `workspaces` 和其他产品域的边界。
3. 如果 `README.md` 中出现跳转或引用，再顺着引用去找相关主题目录。
4. 最后再看更细的实现或流程文档，避免一开始就陷入叶子文件。

这个顺序的好处是先建立“这个目录是什么”，再去看“它和谁有关”。

## 常见误区

- 把 `docs/prds/workspaces` 当成实现代码目录。根据当前片段，它更像产品文档目录，不是功能代码目录。
- 一上来就按“每个叶子文件”理解。这里当前可见结构很浅，先读 `README.md` 才能知道后续该去哪里。
- 误以为没有子目录就没有信息。实际上这种目录常常把信息收敛在 `README.md` 中，入口文件本身就是核心内容。
- 把相邻主题目录混为一谈。`workspaces` 只是 `docs/prds` 下的一个独立主题，应先确认它自己的边界，再和 `conversations`、`previews` 等目录做关联。
- 过度解读当前片段。由于只看到了目录层级，没有读取 `README.md` 内容，涉及具体流程和职责的地方都应保留“根据当前片段推断”的表述。
