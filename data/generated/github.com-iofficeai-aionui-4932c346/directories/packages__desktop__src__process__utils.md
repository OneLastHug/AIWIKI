## 常见误区

第一个误区是把 `process/utils` 当成渲染进程公共工具目录。根据项目架构说明，`packages/desktop/src/process/` 属于主进程侧，不能混入 DOM、React 组件、浏览器事件或渲染层状态管理。即使工具函数看起来“通用”，只要它放在 `process` 下，就应优先按主进程约束理解。

第二个误区是只看工具函数文件名，不看调用方。工具目录的价值不在于每个函数单独做什么，而在于它们被主流程、IPC handler、窗口管理或本地服务怎样复用。没有调用链，很容易误判某个工具的重要性。

第三个误区是默认 `utils` 一定是稳定公共 API。很多项目里的 `utils` 只是局部复用层，不一定承诺跨模块、跨进程或跨包稳定。阅读时要观察是否有统一导出、是否被大量模块依赖、是否有测试覆盖，再判断它是不是关键基础设施。

第四个误区是忽略主进程和渲染进程的边界。主进程工具可以使用 Node.js、Electron 主进程 API、文件系统和系统能力；渲染进程则不能直接依赖这些实现。若发现某个工具同时被 renderer 和 process 使用，就需要重点确认它是否被放在了更合适的 common/shared 位置，或者是否通过 preload/IP C 做了隔离。

第五个误区是把当前任务路径视为一定存在。当前片段显示 `packages/desktop/src/process/utils` 无法定位，因此最可靠的结论不是编造目录结构，而是先承认路径证据不足。后续阅读应从实际存在的桌面端源码根目录重新建立地图。
