- `apps/desktop/src/...` 下的页面、布局、状态模块：工具函数的上层使用者；
- 任何 `utils` 的 `index.ts` 或按功能拆分的纯函数文件：工具的源头位置。

这个顺序的核心是先确认“目录是否真实存在”，再看“它如何被使用”。否则很容易把不存在的目录当成既成结构去记忆。

## 常见误区

1. 把 `utils` 当成“杂物箱”。  
   真正健康的 `utils` 目录应该有明确职责边界，否则很快变成难以维护的公共垃圾场。

2. 只看工具函数，不看调用方。  
   `utils` 的价值不是函数本身，而是它被谁依赖、依赖频率如何、是否导致上层耦合。

3. 误把 `apps/desktop/src/common` 和 `packages/desktop/src/common` 混为一体。  
   根据当前片段推断，仓库的桌面端源码更像是以前者为中心组织的，路径名上的 `packages/desktop` 目前没有被确认。

4. 看到“common”就默认所有东西都能放进去。  
   `common` 和 `utils` 都应该保持克制，能放进去的不等于应该放进去。
